# RAG Streamlit Frontend

Фронтенд RAG-системы: загрузка документов, поиск/ответы по ним и просмотр
источников с подсветкой найденных фрагментов.

## Место в системе

```
┌─────────────────┐   POST /pipeline/process    ┌──────────────────┐
│  Streamlit UI   │ ──────────────────────────► │ rag_save_pipline │  (векторизация + граф)
│  (этот репо)    │      (s3_keys, dataset)     └──────────────────┘
│                 │                              ┌──────────────────┐
│                 │ ──── POST /query ──────────► │ rag_retrive_docs │  (ответ + источники)
│                 │      (query) → answer+srcs  └──────────────────┘
│                 │ ──── put/get объектов ─────► [ S3 / MinIO ]
└─────────────────┘
```

- **Загрузка:** файлы заливаются напрямую в S3 (фоновые потоки, прогресс в
  реальном времени), затем ключи отдаются сервису обработки.
- **Вопрос:** уходит в retrieval-сервис, который возвращает готовый ответ и
  документы-источники с presigned-ссылками и метаданными (`s3_key`,
  `doc_items` с bbox для подсветки).
- **Просмотр:** байты документа читаются из S3 (кэшируются) и рендерятся по
  типу (PDF с рамками, DOCX с подсветкой, таблицы, изображения, текст…).

## Структура

```
src/
  app.py                     # точка входа: page_config → auth → навигация
  config.py                  # типобезопасный конфиг из окружения
  state.py                   # инициализация st.session_state
  auth/                      # логин/логаут на streamlit-authenticator (cookie)
  services/
    s3.py                    # заливка и кэшированное чтение объектов
    process_client.py        # клиент сервиса обработки (+ретраи)
    retrieval_client.py      # клиент сервиса поиска (+ретраи, +кэш ответов)
  ui/
    chat.py                  # страница «Чат» (вопрос → ответ → источники)
    upload.py                # страница «Загрузка» (+прогресс, +история)
    sources.py               # карточки источников под ответом
    preview/                 # предпросмотр по типу файла
```

## Запуск

```bash
cp .env.example .env         # заполнить секреты и адреса сервисов
docker compose up --build    # UI на http://localhost:8501
```

Локально без Docker:

```bash
uv sync                              # ОБЯЗАТЕЛЬНО: ставит streamlit-authenticator и др.
uv run streamlit run src/app.py      # точка входа — только этот файл
```

> Запускать нужно именно `src/app.py` из корня репозитория. Отдельные страницы
> (`src/ui/chat.py` и т.п.) — не точки входа: они поднимаются через `app.py`
> (аутентификация, состояние, навигация) и напрямую не запускаются.
> После изменения зависимостей всегда `uv sync` — иначе `ModuleNotFoundError`.

## Конфигурация

Все параметры — через окружение (`.env`), см. `.env.example`. Ключевое:

| Переменная | Назначение |
|---|---|
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | учётка для входа |
| `AUTH_COOKIE_KEY` | секрет подписи cookie сессии (задать в проде) |
| `S3_*` | доступ к хранилищу исходников |
| `PROCESS_URL` / `PROCESS_API_KEY` | сервис обработки |
| `RETRIEVAL_URL` / `RETRIEVAL_API_KEY` | сервис поиска (без него чат покажет «не подключён») |

## Заметки

- **Прогресс обработки.** Сервис обработки принимает работу асинхронно и не
  отдаёт статус выполнения, поэтому в реальном времени показывается только
  стадия заливки в S3; постановка в обработку отмечается как «принята». Для
  полноценного прогресса нужен статус-эндпоинт на стороне `rag_save_pipline`.
- **Аутентификация.** Один админ-аккаунт, сессия в подписанной cookie
  (переживает refresh). Пароль хэшируется bcrypt на лету.
